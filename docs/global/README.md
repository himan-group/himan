# himan 全周期版本规划与技术路线图

> 状态说明：本文是长期路线图和历史阶段规划，不是当前 CLI 行为的完整事实源。当前实现请优先参考仓库根目录 [README.md](../../README.md)、[v1.0 当前进展](../v1.0/README.md) 和 [Codex repo map](../codex/repo-map.md)。

## 1. 产品长期目标

`himan` 定位为 AI Coding 时代的 Prompt / Agent 资产管理系统，提供从本地开发到团队发布的完整闭环能力。

长期目标：
- 统一管理 rule / command / skill 等资产
- 基于 Git 实现可追溯、可回滚的资源级版本治理
- 支持团队协作、权限控制与可观测性
- 逐步演进为可托管的远程 Registry 平台

---

## 2. 版本演进规划

在 blueprint 与本路线图基础上整理的 **v1.0 功能边界与验收**，见 [v1.0 规划](../v1.0/README.md)；**落地顺序与检查点**见 [v1.0 执行方案](../v1.0/impl.md)。

### 阶段 1：MVP（1 周内可交付）

> 历史规划：当前实现已超过此阶段范围，已支持 `rule` / `command` / `skill`、lock、多 agent 和命名 source。

范围：
- 单 repo
- 仅支持 `rule`
- 本地 CLI
- 基于 Git Tag 的资源级版本管理

目标：
- 跑通 `init -> list -> history -> install -> dev -> publish` 全链路
- 可在真实项目中安装并迭代 rule

里程碑：
- D1-D2：基础骨架、资源扫描、历史查询
- D3-D4：安装与 dev 工作流
- D5：发布闭环
- D6-D7：测试、文档、可用性修复

---

### 阶段 2：增强版（2-4 周）

新增能力：
- `command` / `skill` 类型支持
- lock 文件（项目依赖快照）
- 多 repo 管理
- 发布前校验（lint / schema / compatibility）
- PR 驱动发布（可选）
- 本地索引缓存（例如 `index.json`）

目标：
- 提升团队可复现能力与发布稳定性
- 支持多来源资产的统一检索与安装

---

### 阶段 3：团队协作版（1-2 月）

新增能力：
- 远程 registry（托管索引与元数据）
- 组织与权限控制（读写、审核、发布策略）
- 审批流（review gate）
- 版本策略与兼容性约束（breaking change guard）

目标：
- 从个人工具升级为团队基础设施
- 形成标准化 PromptOps 流程

---

### 阶段 4：差异化智能版（持续演进）

新增能力：
- AI 语义搜索（按意图找资源）
- Prompt ranking（质量/使用率驱动推荐）
- usage analytics（安装、调用、效果指标）
- 变更影响分析（规则更新对项目影响）

目标：
- 从资产管理升级为智能决策系统
- 建立可度量的 Prompt 资产运营能力

---

## 3. 技术路线图

### 3.1 总体架构路线

- V1（MVP）：本地优先
  - Git repo 作为 source of truth
  - `~/.himan/repos`（仓库缓存）
  - `~/.himan/store`（不可变版本缓存）
  - 项目目录软链引用（运行态）

- V2（增强）：多仓与锁定机制
  - 多 repo 聚合索引
  - lock 文件保障可复现
  - 发布前规则校验与兼容性检查

- V3（团队）：远程控制面
  - registry API + metadata service
  - 权限与审计体系
  - Web/CLI 双入口

---

### 3.2 关键技术演进

- 版本治理：Git Tag -> Tag + Lock -> Registry Semver Governance
- 分发方式：本地软链 -> 可选拷贝/镜像 -> 远程分发
- 索引检索：文件扫描 -> 本地索引 -> 语义索引
- 发布流程：CLI 直推 -> PR gate -> Policy-driven 发布
- 可观测性：日志 -> 指标 -> 资产生命周期分析

---

## 4. 组织与交付规划

### 4.1 交付节奏

- 每阶段结束必须输出：
  - 可运行 CLI
  - 回归测试结果
  - 文档更新（命令、目录、示例）
  - 风险与未决项清单

### 4.2 验收基线

- 功能完整性：主流程可跑通
- 稳定性：幂等、错误可诊断、失败可恢复
- 可维护性：模块化结构、可测试、接口清晰
- 可扩展性：新增资源类型不破坏已有命令模型

---

## 5. 全周期风险与应对

- Git 状态冲突：发布前强制 preflight（干净工作区、远端可达）
- 软链兼容问题：明确平台支持矩阵，Windows 放入后续版本
- 结构漂移：可选 `himan.yaml` 的 schema 版本化与入口文件 preflight
- 版本不一致：Tag 作为唯一版本事实来源
- 团队滥发布：引入审批 gate 与权限分层

---

## 6. 结果导向的一句话

`himan` 的工程目标是把 Prompt 资产管理从“文件复制”升级为“可治理、可发布、可协作的标准化系统”。
